# Threads

A thread is a **map of a capability that spans multiple weeks, seasons or files** —
structural knowledge with no natural home in any single work record.

Rules, borrowed from the ACT system because they are what keep threads from rotting:

- **A map, not a store.** Detail lives in the work records and the code. A thread
  points at where things are and explains how they connect.
- **No status.** Status lives in `seasons/<year>/SEASON_INDEX.md`, one place per fact.
  A thread that starts tracking progress will go stale and start lying.
- **Every claim is labelled** — **verified (date)** · **asserted** · **doc**.
- **Update the `Last verified` header** whenever you touch it.

Add a thread only when you catch yourself re-deriving the same cross-cutting picture.
Two or three is a healthy number; a dozen means detail has leaked in from elsewhere.
